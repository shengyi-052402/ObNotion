# 设计模式

设计模式是针对软件设计中普遍存在、反复出现的各种问题所提出的解决方案。遵循面向对象设计原则（如开闭原则、单一职责等），能够显著提高代码的可复用性、可读性与可维护性。

## 正文

### 1. 工厂方法模式 (Factory Method)
用于解耦对象的创建与使用，彻底解除业务层与具体实现类的强耦合。
- **简单工厂**：不属于 23 种经典设计模式。由一个静态工厂方法根据传入参数创建具体产品。增加新产品时必须修改工厂方法代码，违背了**开闭原则**。
- **工厂方法**：定义一个创建对象的抽象工厂接口，让子类工厂决定实例化哪一个具体产品。完全遵循开闭原则（扩展时只需新增具体产品与具体工厂子类），但会带来类爆炸。
- **抽象工厂**：能够创建一组相关或相互依赖的多等级产品（产品族）。例如一个超级风味工厂，既能生产美式风味产品（美式咖啡、抹茶慕斯），也能生产意式风味产品（拿铁咖啡、提拉米苏）。

### 2. 工厂+策略模式重构 (消除冗长 if-else)
只要代码中出现冗长的 `if-else` 或 `switch` 分支判断，均是策略模式大显身手的高频场景。

#### 经典业务场景：多种登录方式 (用户名密码、短信验证码、第三方微信)
传统模式会在 Service 中使用大量的 `if (type.equals("account")) ... else if ...`，难以扩展且违反开闭原则。

#### 工厂+策略完美解耦：
1. **抽象策略接口**：
   ```java
   public interface UserGranter {
       LoginResp login(LoginReq loginReq);
   }
   ```
2. **具体实现注入 Spring**：分别创建 `AccountGranter`、`SmsGranter`、`WeChatGranter` 类，实现接口并标注 `@Component`。
3. **上下文环境（策略工厂）**：
   ```java
   @Component
   public class UserLoginFactory implements ApplicationContextAware {
       private static Map<String, UserGranter> granterPool = new ConcurrentHashMap<>();
       @Autowired
       private LoginTypeConfig loginTypeConfig; // 从 yml 配置中读取类型与 Bean 名称映射
       
       @Override
       public void setApplicationContext(ApplicationContext applicationContext) {
           loginTypeConfig.getTypes().forEach((k, v) -> {
               granterPool.put(k, (UserGranter) applicationContext.getBean(v));
           });
       }
       public UserGranter getGranter(String grantType) {
           return granterPool.get(grantType);
       }
   }
   ```
4. **简洁的业务层代码**：
   ```java
   @Service
   public class UserService {
       @Autowired private UserLoginFactory factory;
       
       public LoginResp login(LoginReq loginReq) {
           UserGranter granter = factory.getGranter(loginReq.getType());
           if (granter == null) { return failResp(); }
           return granter.login(loginReq);
       }
   }
   ```
   **优势**：UserService 极其清爽。未来如果增加 QQ 登录，只需新建 `QqGranter` 并在 `application.yml` 的 `login.types` 下追加一条配置即可，**零修改**原有业务代码，完美贯彻开闭原则。

### 3. 责任链模式 (Chain of Responsibility)
- **概念**：将请求的处理者连成一条链，使请求沿着链条传递，直到有对象处理或链条结束。避免了请求发送者与多个可能处理者之间的强耦合。
- **典型实现**：
  - **Servlet Filter 过滤器**：在进入 Servlet 之前对请求进行链式过滤处理。
  - **Spring MVC Interceptor 拦截器**：拦截 Controller 方法的执行过程。

### 4. Spring 框架内部的经典设计模式
Spring 在底层将设计模式应用得淋漓尽致：
- **单例模式 (Singleton)**：Spring 中的 Bean 默认都是单例的。通过注册表缓存（SingletonObjects Map）确保在容器中只存在唯一的 Bean 实例。
- **代理模式 (Proxy)**：AOP 的基石。基于 JDK 动态代理（针对实现接口的类）或 CGLIB 动态代理（基于继承生成子类，针对普通类）在不改变原代码的情况下为方法进行增强。
- **模板方法 (Template Method)**：JdbcTemplate 封装了打开连接、准备语句、执行 SQL、处理异常、关闭连接的固定骨架，将具体的 SQL 语句和结果集解析暴露给子类或回调实现。
- **观察者模式 (Observer)**：Spring 的事件广播器。通过 `ApplicationEvent`（事件）、`ApplicationListener`（监听器）和 `ApplicationEventPublisher`（发布器）实现组件间的松耦合通知。
