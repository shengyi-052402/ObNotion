# MySQL

当前 MySQL 资料已经覆盖基础问答和性能优化规范两条线，可以同时支持面试复习和日常开发实践。

## 正文

- 原理层面，重点是存储引擎（InnoDB）、B+树索引、事务 ACID 属性与隔离级别、锁机制和 Redo/Undo/Binlog 日志。
- 底层机制深挖：
  - **B+ 树索引**：为什么用 B+ 树？因为非叶子节点只存储索引，叶子节点存储完整数据且以双向链表相连，极大减小磁盘 I/O 次数，并天生支持高效范围查询。
  - **MVCC 实现原理**：多版本并发控制是实现“读已提交（RC）”与“可重复读（RR）”隔离级别的核心。底层依赖 **3 个隐藏字段**（`DB_TRX_ID`最新事务ID、`DB_ROLL_PTR`回滚指针等）、**Undo Log（回滚日志链）** 以及 **ReadView（一致性视图）**。
    - **ReadView 判定逻辑**：ReadView 包含当前活跃的未提交事务 ID 列表。对于要读取的数据版本，若其 `trx_id` 小于活跃事务的最小值，说明事务已提交，对当前事务**可见**；若大于活跃最大值，说明是未来事务，**不可见**；若处于活跃区间内，则在其列表中即未提交，**不可见**（对于 RR，ReadView 在事务启动时首次生成，后续复用；对于 RC，每次 SELECT 都会重新生成）。
    - **快照读与当前读**：快照读是普通的 SELECT（基于 MVCC 读历史版本，不加锁）；当前读是 `SELECT ... FOR UPDATE` 或 `LOCK IN SHARE MODE` 以及增删改（读取最新数据，强行加锁）。
  - **锁机制**：InnoDB 支持行锁（Record Lock）、间隙锁（Gap Lock，锁定开区间，防止插入，**解决可重复读级别下的幻读问题**）和临键锁（Next-Key Lock，行锁与间隙锁的组合，左开右闭区间，为默认加锁基本单位）。还有表级的意向排他锁（IX）/意向共享锁（IS），用以快速判断表中是否存在行锁，提升加锁效率。
  - **主从复制与分库分表**：主从基于 **binlog** 异步/半同步复制；当单表数据量超千万、写入遭遇 I/O 瓶颈时，需采用分库分表（按 ID 哈希或日期范围分片），解决单机性能瓶颈。
- 使用层面，重点是 SQL 基础、字段设计、命名规范、索引设计和操作规范。
- 面试向资料适合建立问题清单，规范向资料适合沉淀成长期约束。
