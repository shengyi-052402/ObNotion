# 常见技术与系统场景

本页沉淀了系统开发中最普遍的通用技术落地场景（单点登录 SSO、RBAC 权限设计、数据加密安全性），以及系统上线后的运维、诊断与日志采集体系（ELK 集群容器化搭建、Linux 日志过滤实操、Arthas 线上诊断、性能压测指标）。

## 正文

### 1. 单点登录与权限认证
- **单点登录 (SSO, Single Sign On)**：指在多个应用系统中，用户只需要登录一次，就可以访问所有相互信任的子系统。
  - **分布式 JWT 网关方案**：用户向网关发起登录请求，认证通过后后端生成 JWT 令牌并写入客户端 Cookie 或 LocalStorage。再次访问子服务时，网关拦截请求，统一校验 JWT 令牌有效性，再路由至目标微服务，以此避免子系统之间 Session 不共享的问题。
- **权限认证 (RBAC 模型)**：基于角色的访问控制（Role-Based Access Control）。
  - **五表关联**：用户表、角色表、权限表、用户角色中间表、角色权限中间表。数据流转为：用户登录 -> 查询拥有的角色 -> 根据角色加载拥有的权限。实际开发常借助于 **Spring Security** 或 Apache Shiro 安全框架实现。

### 2. 上传数据的安全性控制 (敏感数据加密)
网络传输过程中面临数据泄露风险，需要合理选择加密手段：
- **对称加密 (AES/DES)**：
  - **机制**：加密与解密使用相同的密钥。
  - **特点**：计算量小、加密速度快、效率极高。但安全性相对稍弱（需事前安全交换密钥）。
  - **场景**：一般用于数据库中对用户手机号、身份证等敏感但又需要解密的数据进行字段加密存储。
- **非对称加密 (RSA/RS256)**：
  - **机制**：由一对密钥组成：公钥（公开给客户端加密）与私钥（服务器保管解密）。公钥加密的数据只有私钥能解密，反之私钥加密的数据只有公钥能解密。
  - **特点**：安全性极高，但加密解密计算开销大、速度慢。
  - **场景**：常用于数字签名、接口防篡改校验以及客户端少量敏感参数（如登录密码）的高安全级加密传输。

### 3. ELK 日志采集系统搭建
- **ELK 组件职能**：
  - **Elasticsearch (ES)**：近乎实时的分布式全文检索与分析引擎。
  - **Logstash**：数据收集、过滤与统一化流转引擎。
  - **Kibana**：强大的数据可视化与直观搜索面板。
- **Docker 容器化互联配置**：
  1. 创建统一网络：`docker network create elk-net`，以使三大组件容器互联。
  2. 启动 ES：挂载外部 data、plugins 目录，限制启动内存（`-e "ES_JAVA_OPTS=-Xms512m -Xmx512m"`），单节点运行。
  3. 启动 Kibana：加入 `elk-net` 网络，指定宿主地址，启用中文汉化参数 `I18N_LOCALE=zh-CN`。
  4. 启动 Logstash：挂载修改其 `logstash.conf` 配置文件，设置输入源为 TCP（开启 `json_lines` 解码，监听 5044 端口），输出源对接 ES 地址，并按每日日期动态创建索引（`log-%{+YYYY.MM.dd}`）。
- **Spring Boot 应用对接**：引入 `logstash-logback-encoder` 依赖，配置项目 resource 下的 `logback-spring.xml`。通过 `<appender class="net.logstash.logback.appender.LogstashTcpSocketAppender">`，将应用控制台日志及系统文件日志实时上报给 Logstash 5044 端口。

### 4. 生产排障与性能调优
- **Linux 核心日志搜索指令**：
  - 实时监控：`tail -f xxx.log` 或带行数 `tail -n 100 -f xxx.log`。
  - 范围搜索：`sed -n '/开始时间/,/结束时间/p' xxx.log`。
  - 行号及过滤：`cat -n xxx.log | grep "debug" | more`。
  - 截取行号输出：`cat -n xxx.log | tail -n +100 | head -n 100`（查看第 100 到 200 行）。
- **远程 Debug 实战**：
  - 在无法直接操作生产环境时，可以通过测试环境进行远程调试。
  - **服务端配置**：启动 jar 包时加入 JVM 参数：`java -jar -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=5005 myapp.jar`。
  - **本地 IDE 配置**：本地 IDEA 中新建 `Remote JVM Debug` 配置，填写对应的远程服务器 IP 和 5005 端口，启动调试即可打断点跟进。*注意：本地与远程的代码必须保持绝对一致。*
- **Arthas (阿尔萨斯) 线上诊断能力**：
  - 阿里巴巴开源的 Java 诊断利器，无需重启即可排查 CPU 飙高、方法耗时、内存泄漏等问题。
  - 核心命令：`dashboard`（全局概览）、`thread -b`（一键查找死锁线程）、`trace`（追踪方法内部调用路径及耗时，极速定位慢接口原因）、`watch`（观测方法入参返回值）。
- **压测与系统瓶颈定位**：
  - **指标体系**：吞吐量 (TPS)、每秒查询数 (QPS)、并发数、平均响应时间 (RT)、CPU/内存利用率、磁盘与网络 I/O。
  - **工具选择**：Apache JMeter 或 LoadRunner。
  - **定位思路**：项目上线前利用压测预估系统极限；上线后借助 Prometheus + Grafana 进行系统监控，使用 SkyWalking 等追踪调用链条慢节点，最后通过 Arthas 或 JVM 命令细化排查。
