# Redis

当前 Redis 资料以面试问题为主，已经覆盖数据结构、持久化、淘汰策略和集群等核心内容，足够建立 Redis 的基础知识骨架。

## 正文

- 重点主题包括数据结构（String/List/Hash/Set/ZSet及底层ZipList/SkipList）、线程模型（单线程高性能，基于 **I/O 多路复用**）、持久化（RDB 快照与 AOF 日志追加）、缓存淘汰与过期、集群（主从、哨兵、Cluster分片）。
- 生产实战与高阶方案补全：
  - **单线程高性能本质**：纯内存操作、优秀的数据结构设计、基于 epoll 的 I/O 多路复用机制，避免了多线程上下文切换和竞争锁的开销。
  - **三缓存问题防护**：
    - **缓存穿透**（查不存在的值）：缓存空对象；使用**布隆过滤器**（Bloom Filter）在网关层前置拦截。
    - **缓存击穿**（热点 Key 过期，突发巨量并发）：设置热点数据**永不过期**；加载时使用**互斥锁**（如 Redis `setnx` 或 JVM 本地锁）确保仅一个线程去查库重建缓存，其他线程等待重试。
    - **缓存雪崩**（大量 Key 同时过期或 Redis 宕机）：将 Key 的过期时间设置一个**随机偏差值**，避免同时失效；搭建高可用 Redis 集群；多级缓存方案；本地限流降级。
  - **双写一致性机制**：
    - 读多写少强一致：使用 Redisson 的 **读写锁**（ReadWriteLock，读锁共享，写锁互斥，保证读写绝对安全但性能受写限制）。
    - 最终一致性：**延迟双删**（先删缓存 -> 写库 -> 延迟 500ms 再删缓存，防止主从同步延迟导致旧数据回写）；或通过** canal 监听 MySQL binlog**，异步发送 MQ 消息清理 Redis 缓存（极力推荐，解耦且可靠）。
  - **分布式锁（Redisson 机制）**：基于 `setnx` 锁存在过期时间难以估算问题。Redisson 采用 **“看门狗（Watchdog）”** 机制，当线程获得锁后，启动后台守护线程，默认每 10s 检查一次，若线程未完成则为其自动续期，防止业务没执行完锁就被释放。支持可重入。针对 Redis 集群主从切换导致丢锁问题，可采用 **红锁（RedLock）** 机制。
